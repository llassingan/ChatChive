# Trademarks

The MIT license in `LICENSE` covers the source code. It does not cover the name
**ChatChive** or the visual mark that identifies this project.

## What the license covers, and what it does not

`LICENSE` grants permission to use, copy, modify and distribute the code, and to
sell software built from it. That grant is deliberate and it is not narrowed
here: you can fork this project, change it, and ship it.

Two things stay with the project:

1. **The name.** A fork must not present itself as ChatChive, and a modified
   version must not use the ChatChive name as its own. Rename your fork and make
   clear that it is a different product.
2. **The mark.** The logo artwork that identifies this project is part of the
   ChatChive identity. A fork must not use it as its own branding.

A fork that keeps the copyright notice in `LICENSE` (MIT requires that it does)
and renames itself is fully compliant.

## The MIT position

ChatChive is MIT-licensed, and it stays MIT. This closes the open question in
`PRD.md` §11 and §15: the alternative considered was a copyleft license
(AGPL-3.0 or MPL-2.0) to keep forks open, and it was not chosen. MIT means forks
may rebrand and sell, and the project accepts that trade.

The reasoning: the code ships to every visitor's browser in a
client-side app, so hiding it is not possible and obfuscating it would work
against the promise that a visitor can read what runs on their device. What
actually distinguishes this project is not the license. It is the name, the
canonical release, and being the version that keeps pace with WhatsApp's export
format.

The MIT grant is a license for code, not for identity: the name and mark stay
out of scope as described above.

## Not affiliated with WhatsApp or Meta

ChatChive is an independent project. It is not affiliated with, endorsed by, or
connected to WhatsApp or Meta Platforms, Inc. "WhatsApp" is a trademark of Meta
Platforms, Inc., and this project uses the word only to describe the file format
it reads: the plain-text export that WhatsApp itself produces.

## Registration

The name is not registered as a trademark, in any jurisdiction. That is a
statement of current fact, not a plan. If the project grows, registering is worth
considering, and this section changes when it happens.

Contact details for trademark questions are not decided yet. Until they are,
raise the question as a GitHub issue in this repository.
